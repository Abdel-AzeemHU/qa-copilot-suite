# Deployment Guide — Qaera

## 1. Prerequisites

- **Node.js 20+** (`node --version`)
- **npm 10+**
- A **PostgreSQL** database. Options:
  - [Railway](https://railway.app) — easiest, free tier available
  - [Render](https://render.com) — free tier PostgreSQL (90-day expiry on free plan)
  - [Supabase](https://supabase.com) — generous free tier
  - [Neon](https://neon.tech) — serverless Postgres, free tier
- Git + the repository cloned locally

---

## 2. Local development setup

```bash
git clone <repo-url>
cd qaera
npm ci

# Copy example env file and fill in values
cp .env.local.example .env.local
# Edit .env.local — set DATABASE_URL and DIRECT_URL to your local Postgres
# (or use a cloud Postgres for local dev too — just set sslmode=require)

# Push schema to database (creates tables without a migration history)
npx prisma db push

# Start dev server
npm run dev
```

Open http://localhost:3000 and register your first account.

## 3. Database setup

### Railway
1. Create a new Railway project → **Add a service** → **Database** → **PostgreSQL**
2. Click on the Postgres service → **Connect** tab
3. Copy the **DATABASE_URL** (it looks like `postgresql://postgres:...@...railway.internal:5432/railway`)
4. Set `DATABASE_URL` and `DIRECT_URL` to this value in your environment

### Render
When using `render.yaml` (see section 6), the database is created automatically and the connection string is injected.

### Supabase
1. Create a new project at https://supabase.com
2. Go to **Settings** → **Database** → **Connection string** → **URI**
3. Use the **Session mode** (port 5432) URL as `DIRECT_URL`
4. Use the **Transaction mode** (port 6543) URL as `DATABASE_URL` (for PgBouncer compatibility — add `?pgbouncer=true`)

### Neon
1. Create a project at https://neon.tech
2. Copy the **connection string** from the dashboard
3. Set both `DATABASE_URL` and `DIRECT_URL` to this value (Neon uses its own pooler internally)

## 4. Environment variables

All variables are documented in `.env.local.example`. Summary:

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes | Postgres connection string (pooled OK) |
| `DIRECT_URL` | Yes | Direct (non-pooled) Postgres connection for migrations |
| `AUTH_SECRET` | Yes | NextAuth secret — generate with `openssl rand -base64 32` |
| `NEXTAUTH_URL` | Yes | Full URL of your deployment (e.g. `https://yourapp.up.railway.app`) |
| `ENCRYPTION_KEY` | Yes | AES-256-GCM key for encrypting user API keys — generate with `openssl rand -base64 32` |
| `NEXT_PUBLIC_APP_URL` | Yes | Same as NEXTAUTH_URL — used for invite links and OG tags |

**Connection pooler note:** When using PgBouncer or a similar pooler, append `?pgbouncer=true` to `DATABASE_URL`. Set `DIRECT_URL` to the direct (non-pooled) connection so `prisma migrate deploy` works correctly.

## 5. Deploy to Railway

1. **Create project** at https://railway.app → **New Project** → **Deploy from GitHub repo**
2. **Add Postgres** → click **+ New** → **Database** → **Add PostgreSQL**
3. **Set environment variables** in your web service:
   ```
   DATABASE_URL   = (reference the Postgres DATABASE_URL variable)
   DIRECT_URL     = (same as DATABASE_URL for Railway — no separate pooler)
   AUTH_SECRET    = (generate: openssl rand -base64 32)
   ENCRYPTION_KEY = (generate: openssl rand -base64 32)
   NEXTAUTH_URL   = https://<your-service>.up.railway.app
   NEXT_PUBLIC_APP_URL = https://<your-service>.up.railway.app
   ```
4. Railway uses `railway.toml` at the repo root — it will:
   - Build with Nixpacks
   - Run `npx prisma migrate deploy && node server.js` on startup
   - Health-check `/api/health`
5. **Deploy** — Railway triggers a build on push to your default branch.

## 6. Deploy to Render (one-click via render.yaml)

1. Fork or push the repo to GitHub
2. Go to https://render.com → **New** → **Blueprint**
3. Connect your GitHub repo — Render reads `render.yaml` and creates:
   - A **Web Service** (`qaera`)
   - A **PostgreSQL** database (`qaera-db`)
4. After creation, set the remaining env vars in the Render dashboard (they are marked `sync: false` in `render.yaml`):
   ```
   NEXTAUTH_URL        = https://<your-render-service>.onrender.com
   NEXT_PUBLIC_APP_URL = https://<your-render-service>.onrender.com
   ```
   `AUTH_SECRET` and `ENCRYPTION_KEY` are auto-generated by Render (`generateValue: true`).
5. Click **Apply** — Render builds and deploys automatically.

## 7. Deploy to Vercel

> **Important caveat:** Vercel serverless functions are stateless — the scheduler loop (`instrumentation.ts`) runs in a long-lived Node process but **Vercel's function instances are torn down after each invocation**. The scheduler will not persist between invocations. Use Railway or Render if you need the scheduler to run continuously. Alternatively, replace the scheduler with [Vercel Cron Jobs](https://vercel.com/docs/cron-jobs).

1. Import the repo at https://vercel.com → **Add New Project**
2. Set **Framework Preset** to `Next.js`
3. Add environment variables (under **Settings** → **Environment Variables**):
   ```
   DATABASE_URL        (your Postgres connection string)
   DIRECT_URL          (direct connection for migrations)
   AUTH_SECRET         (openssl rand -base64 32)
   ENCRYPTION_KEY      (openssl rand -base64 32)
   NEXTAUTH_URL        (https://<your-project>.vercel.app)
   NEXT_PUBLIC_APP_URL (https://<your-project>.vercel.app)
   ```
4. `vercel.json` at the repo root configures the build command (`npx prisma generate && npm run build`).
5. **Deploy** — Vercel builds on each push.

**Note:** Run `npx prisma migrate deploy` manually before the first deployment (or from a CI step), since `vercel.json` does not run migrations at startup. Use a migration script or a one-off Railway/Render/Heroku run for this.

## 8. Post-deploy checklist

- [ ] Visit `/api/health` — should return `{"status":"ok",...}`
- [ ] Register the first user at `/register`
- [ ] Log in and create an organization + project
- [ ] Add your Claude API key in **Settings** (stored encrypted)
- [ ] Send a test invitation to verify the invite URL uses `NEXT_PUBLIC_APP_URL`
- [ ] Confirm `ENCRYPTION_KEY` is set — the app throws at startup if missing
- [ ] Confirm `DATABASE_URL` is set — the app throws at startup if missing

---

## 9. Upgrading (running migrations)

Every deployment runs `npx prisma migrate deploy` automatically (via the start command in `railway.toml` / `render.yaml`). This applies any pending migrations from `prisma/migrations/` without requiring manual steps.

For Vercel, run migrations manually or add a pre-deploy script:

```bash
npx prisma migrate deploy
```

## 10. Local Postgres (Docker quick-start)

If you don't want to use a cloud Postgres for local dev:

```bash
docker run -d \
  --name qaera-db \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=qa_copilot \
  -p 5432:5432 \
  postgres:16-alpine

# Then in .env.local:
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/qa_copilot"
DIRECT_URL="postgresql://postgres:postgres@localhost:5432/qa_copilot"

npx prisma db push
```
